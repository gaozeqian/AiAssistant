## 环境

| 项 | 值 |
|---|---|
| 机器 | Apple Silicon（arm64），macOS 26.7.3 |
| 运行时 | .NET SDK 10.0.404，Release 构建 |
| ASR 引擎 A | sherpa-onnx Paraformer 中文 small（`model.int8.onnx`，77.9 MB 包） |
| ASR 引擎 B | Whisper.net + `ggml-small.bin`（466 MB） |
| KWS 引擎 | sherpa-onnx KWS zipformer wenetspeech 3.3M（int8，epoch-99） |
| OCR 引擎 | macOS Vision `VNRecognizeTextRequest`（zh-Hans/zh-Hant/en-US，经 Swift Helper） |
| 命令 | `--benchmark-asr` / `--benchmark-ocr` / `--benchmark-kws`（均退出码 0） |

## 语料

- **ASR**：10 条，`say` 合成（Eddy / Flo 两个中文普通话音色），16 kHz 单声道 PCM16。
  覆盖陈述句、会议纪要、唤醒词、优先级列举、评审、性能、中英混说、客户反馈、暂停指令、版本发布。
- **OCR**：12 张，960×320 @2x 渲染（实际 1920×640），含浅色/深色、18px 小字号、低对比度灰字、
  中英混排与四行密集文本。
- **KWS（首轮）**：8 条正样本（3 种音色 × 不同语速），5 条负样本共 6.0 分钟。
- **KWS（扩样后）**：13 条正样本（9 种中文音色，含裸唤醒与带命令），
  22 条负样本共 **2.12 小时**（12 条 10 分钟长样本由语料乱序拼接，另 10 条单元样本；
  其中两条刻意大量出现「时光」「你好」用于压误唤醒）。

### ASR 引擎对比（同一语料）

| 引擎 | 成功率 | 平均 CER | 完全匹配 | 耗时（首样本 / 热态） |
|---|---|---|---|---|
| sherpa-onnx Paraformer 中文 small | 10/10 | **12.45%** | 3/10 | 2185 ms / 17–21 ms |
| Whisper.net `ggml-small` | 10/10 | 27.48% | 0/10 | 4925 ms / 214–251 ms |

Whisper 的两点注意事项：

- 2/10 样本输出**繁体字**（`第三會議式進行方案評審`、`先暫停彩集`），而参考与 CER 按简体逐字比较，
  这部分差异会抬高 CER；即使折算，Whisper 在本次语料上仍慢约 10 倍且错误更多。
- 其余错误与 sherpa 类似（`会议剂要`、`签仪`、`优惑`、`ModSOS`），说明合成语料对两个引擎都不算友好。

### KWS

| 语料 / 参数 | 唤醒率 | 误唤醒率 | 延迟中位数 | 未命中 |
|---|---|---|---|---|
| 首轮：8 正 / 6.0 分钟负，score=1.0 | 87.5%（7/8） | 0.00 次/小时 | 1100 ms | `p05-slow` |
| 扩样：13 正 / **2.12 小时**负，score=1.0 | 84.6%（11/13） | 0.00 次/小时 | 1100 ms | `p05-slow`、`p09-reed` |
| 扩样，threshold 0.15 / 0.35（score=1.0） | 84.6%（不变） | 0.00 次/小时 | 1100 ms | 同上 |
| 扩样，**score=3.0**（当前默认） | **92.3%（12/13）** | **0.00 次/小时** | 1100 ms | `p09-reed` |
| 扩样，score=5.0 | 84.6%（11/13） | 0.00 次/小时 | 1100 ms | `p06-question`、`p09-reed` |

调参结论：

- **零误唤醒在 2 小时负样本上始终成立**，对「时光」「你好」类近音文本不敏感。
- `KeywordsThreshold` 在 0.15–0.35 之间对结果无影响，说明漏检不是后验阈值造成的。
- `KeywordsScore` 存在明显最优点：1.0 → 84.6%，3.0 → **92.3%**，5.0 反而回落到 84.6%（`p06` 开始漏检）。
  因此默认值调为 **3.0**，并保留 `AIASSISTANT_KWS_SCORE` / `AIASSISTANT_KWS_THRESHOLD` 覆盖。
- 唯一稳定漏检的是 `p09-reed`（Reed 音色），属于音色覆盖问题，需真人录音验证后再决定是否继续加权重。
- 吞吐：2.12 小时音频评测耗时 **74 秒**（约 100× 实时），可作为发布前常规门禁。

延迟按片段起点计算，因此约等于唤醒词时长；若需「说完到响应」的真实延迟，应把语料裁剪到唤醒词结束处。

## 过程中发现并修复的缺陷

`PngCodec.TryDecodeToBgra32`（原 `LinuxPngCodec`）在 Sub/Up/Average/Paeth 滤波下使用了
**未重建的邻居字节**，导致真实截图（以及本次渲染的 PNG）解码为空白图，OCR 返回空文本。
修复为逐行重建后写入，并新增 6 项覆盖 5 种滤波与跨行混合滤波的回归测试。
该缺陷同样影响 Linux portal/X11 截图路径。

## 复现

```bash
# 1) 模型（不入库）
curl -L -o /tmp/paraformer.tar.bz2 \
  https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-paraformer-zh-small-2024-03-09.tar.bz2
tar -xjf /tmp/paraformer.tar.bz2 -C artifacts/models

# 2) 语料见 docs/testing/golden-sets.md（本基线使用合成语料）

# 3) 运行
AIASSISTANT_SHERPA_MODEL_DIR=artifacts/models/sherpa-onnx-paraformer-zh-small-2024-03-09 \
  AiAssistant.Host --benchmark-asr --samples artifacts/golden/asr --output artifacts/benchmarks/asr.md

# macOS OCR 需要 Swift Helper；从打包产物或 AIASSISTANT_MAC_HELPER_PATH 指定
AIASSISTANT_MAC_HELPER_PATH=artifacts/packages/staging/osx-arm64/AiAssistant.app/Contents/MacOS/aiassistant-mac-helper \
  AiAssistant.Host --benchmark-ocr --samples artifacts/golden/ocr --output artifacts/benchmarks/ocr.md

# KWS：需要 kws/{encoder,decoder,joiner}.onnx + tokens.txt + keywords.txt
# keywords.txt 格式为拼音 token + @显示文本： n ǐ h ǎo sh í g uāng @你好时光
AIASSISTANT_SHERPA_MODEL_DIR=artifacts/models/sherpa-kws \
  AiAssistant.Host --benchmark-kws --samples artifacts/golden/kws --output artifacts/benchmarks/kws.md
```

## 真人语料（AISHELL-1 测试集）

从 HF 镜像拉取 `AudioLLMs/aishell_1_zh_test` 的一个 parquet 分片（2307 条，16 kHz 单声道 WAV +
转写），随机抽取 100 条构成 `artifacts/golden/asr-real`；另用 693 条拼接成 6 × 10 分钟的真人负样本。

| 任务 | 引擎 | 结果 |
|---|---|---|
| ASR 100 条 | sherpa Paraformer 中文 small | **CER 6.34%** |
| ASR 100 条 | Whisper `ggml-small` | CER 17.13%（未归一化 26.56%） |
| KWS 负样本 60 分钟 | sherpa KWS | **0 次误唤醒** |

- sherpa 在真人语料上（6.34%）明显优于合成语料（12.45%），说明合成 TTS 反而是更难的分布。
- Whisper 26.56% → 17.13% 的下降来自繁简归一化；剩余差距主要是数字书写（`2012` vs `二零一二年`）
  与真实误识，仍远差于 sherpa。

### 指标归一化

`CharacterErrorRate.Normalize` 现内置 OpenCC `TSCharacters.txt`（Apache-2.0）繁简映射，
并继续忽略空白/标点/大小写；阿拉伯数字不作转写归一（`2012` 与 `二零一二` 仍计错），报告中如实体现。
