# 回滚手册

> **状态**：living ｜ **最后更新**：2026-11-22 ｜ **适用版本**：0.1.x ｜ **维护触发条件**：回滚路径、备份格式或数据兼容性变化时

> 目标：在 30 分钟内回到「可用且不丢用户数据」的上一版本。

## 1. 前提

- 发布产物保留最近两个版本（安装包 + SHA256），见 `artifacts/packages/` 与 GitHub Release。
- Schema 只向前迁移：**降级应用不能读取更高版本的数据库**。因此回滚必须同时回滚数据。

## 2. 回滚决策

| 症状 | 处置 |
|---|---|
| 新版本启动失败/崩溃，数据库未迁移 | 直接重装上一版本即可 |
| 新版本已迁移 Schema 后出现问题 | 先导出/备份当前数据，再恢复上一版本的备份，最后重装旧版 |
| 数据损坏 | 用最近一次 `--backup` 恢复；无法恢复时保留现场并收集诊断导出 |
| 签名/公证问题 | 重新签名发布，不涉及数据 |

## 3. 标准回滚步骤

1. **停止应用**：托盘退出，确认进程结束。
2. **备份现场**（即使怀疑损坏也要保留）：
   ```bash
   AiAssistant.Host --backup /path/to/rollback-$(date +%Y%m%d-%H%M).enc
   ```
   若应用无法启动，直接复制整个数据目录。
3. **恢复上一版本数据**：
   ```bash
   AiAssistant.Host --restore /path/to/pre-upgrade-backup.enc --confirm-restore
   ```
   该命令会校验备份完整性与 Schema 版本，拒绝更高版本备份。
4. **安装上一版本**：使用保留的安装包覆盖安装（Windows zip/MSI、macOS app、Linux deb/tar.gz）。
5. **验证**：`--startup-check` 输出 OK；抽查时间线、日报、检索与语音日志。
6. **记录**：把故障现象、版本号、回滚时间、数据备份路径写入发布说明与 `docs/status/log.md`。

## 4. 无法回滚数据时

- 不要删除数据目录与 `keystore`。
- 导出脱敏诊断（诊断页 → 生成预览 → 确认导出）。
- 保留 `AiAssistant.Host --startup-check` 的完整输出与错误类型。
- 在修复版本中提供前向修复迁移，而不是要求用户手工改库。

## 5. 校验和

发布时生成：

```bash
sha256sum artifacts/packages/* > artifacts/packages/SHA256SUMS
```

回滚安装前校验下载包与 `SHA256SUMS` 一致。

## 6. 回滚演练

每个发布周期至少演练一次：

- [ ] 用上一版本备份恢复到当前版本成功。
- [ ] 用当前版本备份在上一版本上恢复被正确拒绝（Schema 更新保护）。
- [ ] 回滚后采集、日报、检索、语音四项功能可用。
