# ADR-0009：UTC 时刻 + 发生时本地日期 + 时区的混合时间与日报归档模型

- **状态**：已采纳 (Accepted)
- **日期**：2026-11-20
- **阶段**：S0 / S1

## 背景

若仅存储 UTC 时间戳，用户跨时区出差后回看历史日报会导致“某天的活动漂移到前一天或后一天”；若仅存储本地时间，则在夏令时切换或跨时区连续工作时会导致时间线排序错乱。

## 决策

每条 `ActivityEvent` 通过不可变值对象 `OccurredTimestamp` 同时持久化四个字段：

- `occurred_at_utc`：高精度 UTC 时刻（用于全局严格排序与时间窗口计算）；
- `local_date`：事件发生瞬间所在时区的日历日期 `YYYY-MM-DD`（用于日报归档分区，跨时区旅行后**不重写历史归档日期**）；
- `time_zone_id`：IANA / 系统时区标识；
- `utc_offset_minutes`：事件发生时的 UTC 偏移分钟数。

所有时间获取必须经过 `IClock` 端口，禁止业务代码直接调用 `DateTimeOffset.Now` / `UtcNow`。

## 后果

- 时间线排序严格单调且可重现，历史日报归属稳定，单元测试可通过 `FakeClock` 精确验证跨天与跨时区边界。
