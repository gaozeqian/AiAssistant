# ADR-0001：采用模块化单体与端口适配器架构，而非过早微服务化

- **状态**：已采纳 (Accepted)
- **日期**：2026-11-20
- **阶段**：S0

## 背景

个人活动追踪助手需要在用户桌面长期常驻，同时协调屏幕/窗口/文件/音频采集、预处理、加密存储、日报生成与本地语音交互。若拆分为多个常驻微服务进程，会显著增加本地 IPC 鉴权面、跨进程事务一致性难度、安装包体积以及待机内存（目标 `<400MB`）。

## 决策

1. 主体采用**单进程模块化单体 + 端口与适配器（Hexagonal Architecture）**。
2. 仅在以下明确边界使用外部进程：
   - **macOS Swift Helper**：隔离 ScreenCaptureKit / Vision / CoreAudio / AX 原生框架与 TCC 权限生命周期。
   - **外部推理引擎**：Ollama / LM Studio 等独立模型服务进程。
3. 模块间只能通过 `AiAssistant.Application` 定义的端口接口交互，禁止因同进程而直接引用具体适配器实现。

## 后果

- **正面**：单进程内有界 `Channel` 零拷贝传递帧与控制事件，SQLite 事务与 AES-GCM 媒体存储一致性易于保证，资源占用可控。
- **权衡**：必须用自动化架构测试（`AiAssistant.Architecture.Tests`）强制守护模块边界，防止单体内耦合腐化。
