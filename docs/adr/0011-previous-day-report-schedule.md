# ADR-0011：前一天日报的自动检查与版本追加

- **状态**：已采纳 (Accepted)
- **最后更新**：2026-11-26
- **适用版本**：0.1.x
- **维护触发条件**：自动检查的触发时间、目标日期或版本语义变化时新增 ADR
- **阶段**：S5

## 背景

固定时刻生成当天日报时，生成后的活动不会进入已写入的日报；用户手动生成的日报也可能缺少晚间的活动记录。同时，定时时间只能通过环境变量调整，对桌面用户不友好。

## 决策

1. 自动检查统一针对**前一个本地日期**：
   - 每天在用户配置的时间（默认 `00:30`）检查一次；
   - 应用启动时也检查一次，覆盖关机、休眠或错过定时的情况。
2. 检查按活动记录决定是否入队，绝不生成空日报：
   - 目标日期没有日报：至少存在一条活动记录才入队生成；
   - 目标日期已有日报：存在 `occurred_at_utc` 晚于最新日报 `GeneratedAtUtc` 的活动记录时，以 `ForceOverwrite` 入队，追加新版本；
   - 没有新活动则不入队。
3. 自动触发的入队前检查同一目标日期是否已有待处理/运行中的任务，避免启动检查与定时检查重复入队。
4. 定时时间与启停状态通过日报页的「自动日报」卡片编辑，保存到 `<数据目录>/report-schedule.json`，Worker 每轮读取最新值，无需重启。
5. 环境变量 `AIASSISTANT_REPORT_TIME` / `AIASSISTANT_REPORT_DISABLE_SCHEDULE` 仅在没有已保存的界面设置时作为初始值，供无界面/CLI 启动使用。

## 后果

- 日报覆盖完整自然日，生成后新增的活动可通过自动版本追加补齐。
- 无活动日期不会产生失败任务或空日报。
- 自动检查保持幂等；手动强制重生成仍沿用 ADR-0010 的版本追加语义。
- 自动生成仍是一次快照，运行中的活动不会实时写入已生成的日报。
